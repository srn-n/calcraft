# Bouncy Calculator — Security & QA Audit

**Target:** https://calcraft-rho.vercel.app (build `index-COFXGBuU.js`, identical to `main` @ `1cf8c8c`)
**Date:** 29 Oct 2026 · **Result:** 21 issues found and fixed · 10 themes added (14 → 24) · tests 96 → 113, all passing · `npm audit`: 4 vulnerabilities → 0

> Note: `BOUNCY-CALCULATOR-PROJECT.pdf` in the project describes the old v4 (4 themes, Android WebView). The live app is v5 (Vite, 14 themes, tools, games). This audit is of v5.

---

## How it was tested

Every finding below was **reproduced on the live site** in a real Chromium browser (Playwright), then re-run against the fixed build served with the production security headers.

| Persona | What they did |
|---|---|
| **Class 5 student** | Simple sums, ÷0, tapping 1/x after `=`, holding keys, games |
| **Everyday user** | Tip tool, unit converter, history tape, memory keys, phone layout |
| **Power user** | Keyboard only, paste from Excel / Python / European locale, Ctrl+K palette, Delete key, very long input |
| **Accessibility user** | Keyboard focus in every theme, OS + in-app Reduce Motion, colour contrast (all 24 themes, WCAG 2.1) |
| **Full-stack / security dev** | Source review, HTTP headers, CSP, storage tampering, service worker, dependency audit, DOM-XSS sinks |

## Findings

Severity: 🔴 High · 🟠 Medium · 🟡 Low

### Security

| # | Sev | Issue | Fix |
|---|---|---|---|
| S1 | 🔴 | **No security headers.** No CSP, no `X-Frame-Options`/`frame-ancestors` (clickjackable), no `nosniff`, `Referrer-Policy` or `Permissions-Policy`. Only HSTS was present. | Added `vercel.json`: strict CSP with **no `unsafe-inline` / `unsafe-eval`**, framing blocked, `nosniff`, `no-referrer`, locked-down Permissions-Policy, COOP/CORP. The inline pre-paint script is allowed by SHA-256 hash; a test fails (and prints the new hash) if anyone edits it without updating the policy. Verified: zero CSP violations across all 24 themes. |
| S2 | 🔴 | **Dev-dependency CVEs** (`npm audit`: 2 critical, 1 high, 1 moderate) — Vite 6.3.5 `server.fs.deny` bypass / cross-origin script execution, **combined with `server: { host: true }`**, which exposed the dev server to the whole LAN (e.g. campus Wi-Fi). Also vitest/tinypool RCE gadgets. | Vite → 6.4.5, Vitest → 4.1.12 (**0 vulnerabilities**). Dev server is localhost-only by default; `npm run dev -- --host` when you need your phone. |
| S3 | 🟠 | **Unvalidated localStorage.** Any malformed value bricked the app: a bad `tools` entry stopped the whole keypad from working; a bad `history` broke every `=`. | New `src/core/schema.js` validates and caps every stored value (types, ranges, known keys only, 200 tape items, 400-char expressions). Verified: 5 corrupted-storage cases now boot and calculate normally. |
| S4 | 🟠 | **Service-worker cache poisoning (self-inflicted).** Every navigation — including a 404 or `/licenses.txt` — overwrote the cached app shell. After visiting any bad URL once, **offline the app opened Vercel's 404 page** (reproduced live). | Only a successful HTML response for the app itself can replace the shell; hashed assets cache-first; manifest/icons stale-while-revalidate; cache version bumped so old assets are purged. |
| S5 | 🟡 | `window.bouncy` exposed the writable store to any script on the page. | Frozen, read-only hook: `getState()`, `setTheme()`, `themes`. |
| S6 | 🟡 | Result digits were built as HTML strings with inline `style=` attributes (blocks a strict CSP); expression escaping only covered `<` and `&`. | Built with DOM nodes; full HTML escaping. No `eval` / `Function()` anywhere (the engine's tokenizer → parser design was already solid). |

### Wrong answers (silent maths errors)

| # | Sev | Issue | Fix |
|---|---|---|---|
| M1 | 🔴 | Pasting `1e-7` (from Python/JS) gave **−4.28** — `e` was read as Euler's number. | Pasted e-notation is converted to engineering `E`. Typed `e` is still Euler's number. |
| M2 | 🔴 | Pasting `1,5*2` (European decimal comma) gave **30**. | `1,234` / `1,234,567` = thousands; `1,5` / `3,14159` = decimal. |
| M3 | 🔴 | MR with a negative memory after a number: `3` then MR(−5) became `3−5` = **−2**. Tapping a tape result after `12` glued digits: `12` + `34` → **1234**. | New `insertValue()`: inserts × between values and brackets negatives → `3×(−5)`, `12×34`. Used by MR, tape and "Send to calc". |
| M4 | 🟠 | Chaining from a tiny answer (e.g. `1÷10000000 =` then `+1`) used JS's `1e-7`, which re-parsed as Euler's `e` → wrong result. | Numbers below 10⁻⁶ are always written with `E`. |

### Glitches & animation crashes

| # | Sev | Issue | Fix |
|---|---|---|---|
| G1 | 🔴 | **Ghost game.** Quitting *Estimate* during the 1.3 s between rounds left it running invisibly — it kept looping rounds, playing sounds and **vibrating the phone** while you used the calculator (reproduced: vibration 11 s after quitting). *Make 24* had the same timer leak. | All game timers are tracked and cancelled on quit. Verified: 0 vibrations after quitting. |
| G2 | 🔴 | **In-app Reduce Motion made the caret strobe** (infinite blink squeezed to 1 ms) — and the Phosphor CRT flicker likewise. That's the opposite of what a motion-sensitive user asked for. | Iteration count forced to 1; caret and overlay animations off. |
| G3 | 🟠 | Confetti ignored the in-app Reduce Motion switch (only obeyed the OS setting). | Confetti honours both. |
| G4 | 🟠 | **1/x after `=` did nothing useful** (`5 =` then 1/x → `^(−1)` → "Unexpected ^"). Pressing it first showed an error. | 1/x continues from the answer (→ 0.2); with nothing before it, it's ignored. |
| G5 | 🟠 | Holding ⌫ then switching windows (Alt-Tab) or using two fingers could leave **backspace repeating** / cancel the wrong key's repeat (shared timers). | Per-pointer timers; all holds stop on blur / tab hide. |
| G6 | 🟡 | History sheet on phones vanished instantly instead of sliding down (visibility flipped before the animation). | Visibility now waits for the slide-out. |
| G7 | 🟡 | Cyber HUD: keyboard focus ring invisible (the chamfer `clip-path` cuts off outlines). | Focus drawn inside the shape. |
| G8 | 🟡 | `Delete` wiped the whole expression (power users expect forward delete). | Forward delete, function-aware (`sin(` goes in one press). `Esc` is still AC. |
| G9 | 🟡 | Unbounded input: holding `(` grew the expression without limit (each keystroke re-parsed it). | Capped at 300 characters. |
| G10 | 🟡 | Tip tool "Send to calc" with an empty bill sent `—` into the calculator. Themes button tooltip said "(T)" but T types `tan(`. | Guarded; tooltip fixed. |

### Accessibility — colour contrast

Small text (`--muted`, `--display-muted`: hints, tape times, labels) was below WCAG 4.5:1 in **9 of 14 themes** (worst: Braun operators at 2.3:1). All small-text tokens adjusted to ≥ 4.6:1 with minimal colour shift. All 10 new themes pass 4.5:1 on every text pair.

## Verification

- **113/113 unit tests pass**, including new `tests/security.test.js` (CSP hash, no `unsafe-*`, no inline styles/eval, storage validation) and regression tests for every maths bug above.
- **Production build** served with the exact `vercel.json` headers: 0 CSP violations, 0 console errors, all 24 themes render with no horizontal overflow at phone width.
- **Every reproduced bug re-run** against the fixed build: all pass (1/x → 0.2, `1e-7` → 1e-7, `1,5×2` → 3, MR → −15, 0 ghost vibrations, caret static under Reduce Motion, 5/5 corrupted-storage boots OK, sheet animates closed).
- The service-worker fix was verified by code review and logic; confirm on the live site after deploy (see below).

## Not changed (your call)

- **Brand-colour labels** on Liquid Glass, TE, Solar LCD and Bauhaus tabs/`=` are 3.3–4.3:1 — fine for the big key labels, short of 4.5:1 for the small tab text. Darkening them changes the theme's identity.
- **Hold AC (0.65 s) wipes tape, memory and Ans** with no undo — a kid can lose their history. Consider an "Undo" in the toast.
- **DSEG7 themes** (Solar LCD, Mission Control) can't draw letters, so `sin(` looks odd in those displays.
- **Long expressions can't be finger-scrolled** on phones (`touch-action: none` on the display, needed for swipe gestures). Tap-to-place-caret still works.
- If your Android/Tauri wrapper used `window.bouncy.store`, switch it to `window.bouncy.getState()`.

## Deploy

```bash
npm install          # picks up vite 6.4.5 / vitest 4.1.12
npm test             # 113 passing
npm run build
git add -A && git commit -m "Security hardening, bug fixes, 10 new themes"
git push             # Vercel redeploys
```

After deploy, check headers at securityheaders.com, then: open the app, visit `/nope`, go offline, reload → you should get the calculator, not a 404.
