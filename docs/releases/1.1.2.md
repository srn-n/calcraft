## What changed in 1.1.2

### 1. Edge-to-edge, the standard way (Play recommendation)
- **Asked:** "proceed with the suggestions". This was Play's Production dashboard recommendation
  "Edge-to-edge may not display for all users":
  > From Android 15, apps targeting SDK 35 will display edge-to-edge by default … call
  > EdgeToEdge.enable() for Java for backward compatibility.
- **Cause:**
  - Nothing displayed wrongly. The app already drew behind the bars and sent their sizes to the page
    (`BouncyNative.insets`).
  - But it set this up with the window calls Android 15 deprecated: `setStatusBarColor`,
    `setNavigationBarColor`, `setDecorFitsSystemWindows` and the `shortEdges` cutout mode.
- **Built:**
  - `MainActivity` now extends `androidx.activity.ComponentActivity` and calls
    `EdgeToEdge.enable(...)`, with transparent bars in both light and dark.
  - The bar icon colours still follow the app's theme (`applyBarIcons`), not the system's dark mode.
  - The grey scrim stays off behind 3-button navigation (`setNavigationBarContrastEnforced(false)`).
  - On Android 12+ the theme uses cutout mode `always`. The deprecated bar-colour items were dropped
    from that theme, and `EdgeToEdge` sets them on older versions.
  - **Back is unchanged.** It still uses the platform's own `OnBackInvokedCallback` (Android 13+) and
    `onBackPressed` (Android 12 and older), so Android 15's system "back to home" animation stays.

### 2. R8 optimisation (Play recommendation)
Play's recommendation "Improve your app's memory and performance with R8 optimization" listed three
items:
- **Low obfuscation rate (36%) → 88%.**
  - **Cause:** measured from R8's mapping, 54 of the 69 classes R8 couldn't rename were
    `org.chromium.support_lib_boundary` interfaces from `androidx.webkit`. The system WebView looks
    them up by name, so no keep rule could change that. The app only used that library for
    `WebViewAssetLoader`.
  - **Fix:** `androidx.webkit` is removed. `MainActivity` serves
    `https://appassets.androidplatform.net/assets/…` itself.
  - The path and type rules are in a small plain-Java class, `AssetPaths`:
    - Only plain relative paths under `assets/` are served. Paths with `..`, hidden or empty segments,
      backslashes or NUL are refused.
    - Missing files get a 404, never a network fetch.
    - Every bundled file type gets its proper type. ES modules need `text/javascript`.
  - The same origin is kept, so saved history, themes and settings (localStorage) carry over.
- **Optimised resource shrinking:** on, as the default in AGP 9.
- **Android Gradle Plugin 9.0 or higher:** AGP **8.11.1 → 9.5.3**, and Gradle **8.13 → 9.9.2**, in
  CI. The build script needed no changes for AGP 9's new DSL.
- **Kept:** `androidx.profileinstaller`, which comes with the activity library. It lets Play pre-compile
  startup code so the app opens faster, and its receiver can only be triggered over ADB
  (`android.permission.DUMP`).
- **Removed:** the `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` that `androidx.core` declares (the app
  registers no receivers). **VIBRATE is still the only permission.**

## Tests and checks
- **161 web tests pass.** `npm run build` and `npm run build:android` pass, including the CSP check.
- **New check: `android/checks/AssetPathsCheck.java`,** which CI runs before the Android build. It
  checks that:
  - all 33 bundled files resolve, with a real type
  - `index.html` is `text/html` (UTF-8)
  - the module script is `text/javascript`
  - fonts are binary
  - 15 bad paths are refused (traversal, hidden, empty segment, backslash, NUL, outside the prefix)
- **Release build here** (Android SDK 36, AGP 9.5.3, Gradle 9.9.2): AAB and APK built.
  - **Obfuscation:** 219 of 248 classes renamed (88%; it was 107 classes, 36%).
  - **Bridge names:** all 9 `BouncyNative` methods keep their names in the compiled code (`haptic`,
    `copy`, `paste`, `setBars`, `setCanGoBack`, `ready`, `insets`, `soundAllowed`, `shareApp`).
  - **Manifest:** package `com.simplymadestudio.bouncycalculator`, code 17 / 1.1.2, target SDK 36,
    only VIBRATE.
  - **Size:** APK 682 KB (was 636 KB; the activity library's lifecycle code outweighs dropping webkit).
- **Not checked here:**
  - Lint-vital ran in CI only. Maven Central rate-limited this sandbox when downloading the lint tool.
  - Running the app on a phone: there's no emulator here. Check it on the signed APK (see below).

## Before uploading: test the APK on a phone
Edge-to-edge and the asset loader are the two areas to look at:
1. The app opens to the calculator (not blank), with fonts, themes and icons showing.
2. The status bar and navigation bar are see-through. Their icons stay readable when switching
   between light and dark themes.
3. Back closes the menu or tape, and at home leaves the app with the system animation.
4. The ☰ links (privacy, terms) open in the browser. Share app, copy and paste work.
5. Your saved history and theme are still there after updating from 1.1.1.
